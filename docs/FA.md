# راهنمای فارسی MManager

**MManager** ابزاری برای نصب و مدیریت سرورهای Minecraft روی Ubuntu است. این راهنما بخش پنل وب عمومی، نصب اولیه و مدیریت تنظیمات پنل از طریق CLI را توضیح می‌دهد.

## ۱. نصب

سیستم‌عامل‌های پشتیبانی‌شده در نسخه فعلی: Ubuntu 22.04، 24.04 و 26.04 به‌همراه systemd.

نصب را با دسترسی مدیریتی اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/Amir9831/MManager/main/install.sh | sudo bash
```

اسکریپت وابستگی‌ها و سرویس‌ها را نصب می‌کند، رمز مدیر را می‌سازد و یک مسیر تصادفی با طول و آنتروپی بالا برای پنل تولید می‌کند.

پس از موفقیت بررسی سلامت هر دو سرویس، در نصب تازه رمز مدیر یک‌بار در خروجی ترمینال نمایش داده می‌شود. رمز در فایل `/root/mmanager-admin-credentials.txt` با سطح دسترسی 0600 نیز ذخیره می‌شود. در به‌روزرسانی یا نصب مجدد، رمز قبلی حفظ می‌شود و نمایش داده نخواهد شد.

در پایان نصب، آدرس پنل با این قالب نمایش داده می‌شود:

```text
http://PUBLIC_IP:PANEL_PORT/RANDOM_PATH/
```

- `PUBLIC_IP`: آدرس IPv4 عمومی سرور
- `PANEL_PORT`: پورت TCP پنل
- `RANDOM_PATH`: مسیر محرمانه و تصادفی پنل

رمز مدیر و آدرس پنل در فایل زیر ذخیره می‌شوند:

```text
/root/mmanager-admin-credentials.txt
```

سطح دسترسی این فایل باید فقط برای root باشد (0600). آن را در اختیار دیگران قرار ندهید.

## ۲. دسترسی از اینترنت و فایروال

پنل وب و API موردنیاز مرورگر روی یک پورت TCP مشترک ارائه می‌شوند. سرویس Core/API داخلی جداگانه روی loopback باقی می‌ماند و نباید مستقیماً روی اینترنت منتشر شود.

اگر UFW روی سرور فعال باشد، نصب‌کننده تلاش می‌کند پورت پنل را باز کند. در هر صورت، در پنل مدیریت VPS یا Cloud Firewall نیز باید پورت TCP انتخاب‌شده را مجاز کنید.

برای مشاهده وضعیت UFW:

```bash
sudo ufw status
```

اگر لازم بود پورت را دستی باز کنید (عدد را با پورت پنل خود جایگزین کنید):

```bash
sudo ufw allow PANEL_PORT/tcp
```

در صورت وجود فایروال در سطح ارائه‌دهنده VPS، قانون ورودی TCP متناظر را آنجا نیز اضافه کنید.

### پورت‌های اتصال Minecraft

قوانین فایروال بازی از نصب‌کننده به‌صورت خودکار ساخته نمی‌شوند و باید هم در UFW و هم در فایروال ارائه‌دهنده VPS اعمال شوند:

- **Java Edition:** پورت نمایش‌داده‌شده در پنل را با پروتکل TCP باز کنید.
- **Bedrock قدیمی‌تر (RakNet):** پورت IPv4 با UDP و در صورت فعال‌بودن IPv6، پورت UDP جداگانه IPv6 را نیز باز کنید.
- **Bedrock 1.26.50 و جدیدتر (NetherNet):** پورت `server-port` با پروتکل TCP برای signaling و بازه `49152-49200` با پروتکل UDP برای ترافیک بازی باز باشد.
- **Cross-play:** پورت Java با TCP و پورت Geyser با TCP و UDP باز باشد.

در بخش «تنظیمات سرور» می‌توان IPv4 و IPv6 را مستقل فعال/غیرفعال کرد. IPv4 به‌صورت پیش‌فرض فعال و IPv6 به‌صورت پیش‌فرض غیرفعال است. حداقل یکی از این دو باید فعال بماند. این سیاست با فیلتر شبکه systemd فقط روی همان سرویس اعمال می‌شود؛ UFW و Cloud Firewall به‌صورت خودکار تغییر نمی‌کنند.

نمونه برای Bedrock جدید (پورت TCP را با مقدار پنل جایگزین کنید):

```bash
sudo ufw allow 19132/tcp
sudo ufw allow 49152:49200/udp
```

## ۳. مدیریت پنل از CLI

CLI را با دسترسی مدیریتی اجرا کنید:

```bash
sudo Mmanager
```

از منوی اصلی وارد گزینه **Web panel management** شوید.

### تغییر یا تولید مجدد Path

گزینه تغییر Path را انتخاب کنید. می‌توانید یک مسیر جدید با حداقل ۲۴ نویسه URL-safe وارد کنید یا ورودی را خالی بگذارید تا مسیر تصادفی جدید ساخته شود.

پس از ذخیره، سرویس وب راه‌اندازی مجدد می‌شود. آدرس قبلی دیگر معتبر نخواهد بود؛ آدرس جدید را از گزینه نمایش آدرس پنل دریافت کنید.

### تغییر رمز مدیر

رمز جدید باید حداقل ۱۲ نویسه داشته باشد و دوبار برای تأیید وارد شود. رمز به‌صورت Argon2id هش می‌شود و توکن نشست‌های قبلی باطل می‌شوند؛ بنابراین کاربران باید دوباره وارد پنل شوند.

### تغییر پورت

پورت باید عددی بین 1024 تا 65535 باشد و توسط برنامه دیگری اشغال نشده باشد. پس از تغییر، سرویس وب مجدداً راه‌اندازی می‌شود. اگر پورت جدید در UFW یا Cloud Firewall مجاز نباشد، از بیرون سرور به پنل دسترسی نخواهید داشت.

### نمایش آدرس فعلی

گزینه نمایش URL، آدرس پنل را با IP عمومی، پورت و Path فعلی چاپ می‌کند.

## ۴. امنیت

- Path تصادفی یک لایه دفاعی اضافه است؛ جایگزین رمز عبور و احراز هویت نیست.
- احراز هویت Argon2id و Bearer Token را غیرفعال نکنید.
- Listener داخلی این نسخه از HTTP استفاده می‌کند. برای انتشار واقعی روی اینترنت، HTTPS را با یک Reverse Proxy معتبر مانند Nginx یا Caddy فعال کنید.
- پورت Core/API داخلی را در فایروال عمومی باز نکنید.
- فایل اطلاعات مدیر را با مجوز 0600 نگه دارید و URL کامل پنل را محرمانه تلقی کنید.
- تغییر Path باعث بی‌اعتبارشدن آدرس قبلی می‌شود؛ URL جدید را در محل امن نگه دارید.

## ۵. نصب مجدد و حفظ تنظیمات

نصب مجدد، فایل‌های تنظیمات موجود در `/etc/mmanager` و داده‌ها، دنیاها و بکاپ‌های موجود در `/var/lib/mmanager` را حفظ می‌کند. اگر قبلاً رمز یا Path پنل ساخته شده باشد، نصب مجدد آن‌ها را به‌صورت خودکار تغییر نمی‌دهد.

## ۶. عیب‌یابی سریع

وضعیت سرویس وب:

```bash
sudo systemctl status mmanager-web --no-pager
```

مشاهده لاگ سرویس وب:

```bash
sudo journalctl -u mmanager-web -n 100 --no-pager
```

راه‌اندازی مجدد سرویس:

```bash
sudo systemctl restart mmanager-web
```

اگر پنل از داخل سرور در دسترس است اما از اینترنت باز نمی‌شود، ابتدا پورت TCP را در UFW و سپس در Cloud Firewall ارائه‌دهنده VPS بررسی کنید. همچنین مطمئن شوید IP عمومی و پورت درج‌شده در URL درست هستند.

---

پنل عمومی در نسخه 0.7.0 همچنان HTTP است. MManager قوانین UFW یا Cloud Firewall ارائه‌دهنده VPS را تغییر نمی‌دهد؛ اما گزینه‌های IPv4/IPv6 هر سرور را با فیلتر شبکه systemd در سطح همان سرویس اعمال می‌کند. برای دسترسی اینترنتی امن، HTTPS را با Reverse Proxy معتبر فعال کنید و پورت‌های لازم را خارج از MManager مدیریت کنید.

## ۷. مدیریت تک‌سرور در نسخه جدید

پنل وب فقط یک نمونه Minecraft را مدیریت می‌کند. پس از نصب اولین سرور، فرم راه‌اندازی اولیه دیگر نمایش داده نمی‌شود و پنل به داشبورد همان سرور می‌رود. سرورهای موجود و مسیر دنیاهای قبلی در نصب مجدد حذف نمی‌شوند.

### انتخاب Edition و نسخه

در اولین ورود، یکی از حالت‌های زیر را انتخاب کنید:

- **Java Edition:** سرور رسمی Vanilla یا Paper؛ فهرست نسخه‌های Release از Manifest رسمی Mojang دریافت می‌شود.
- **Bedrock Edition:** نرم‌افزار رسمی Bedrock Dedicated Server برای Linux؛ فهرست نسخه‌های پایدار و checksumها از مخزن داده نسخه‌ها دریافت می‌شوند و فایل اجرایی از دامنه رسمی Minecraft دانلود می‌شود.
- **Cross-play:** سرور Paper به‌همراه Geyser و Floodgate؛ فهرست نسخه‌ها به نسخه‌های دارای build پایدار Paper محدود می‌شود.

برای نصب اولیه، پذیرش EULA لازم است. در حالت Bedrock نیز باید شرایط مجوز نرم‌افزار را بپذیرید.

### تنظیمات سرور

بخش «تنظیمات سرور» فایل server.properties را می‌خواند و تنظیمات پیش‌فرض Java یا Bedrock را از قالب‌های داخل پروژه بارگذاری می‌کند. تغییرات پس از ذخیره روی دیسک ثبت می‌شوند؛ برای اعمال تنظیماتی که نیازمند راه‌اندازی مجدد هستند، سرور را Restart کنید.

قالب‌های مرجع در مسیر mmanager/templates/ قرار دارند:
- java-server.properties
- bedrock-server.properties
- crossplay-geyser.yml

### لاگ و بکاپ

- بخش «لاگ سرور» خروجی سرویس systemd را نشان می‌دهد و هنگام باز بودن این بخش هر ۵ ثانیه تازه می‌شود.
- تهیه بکاپ، در صورت روشن بودن سرور آن را موقتاً متوقف می‌کند تا آرشیو سازگار تهیه شود و سپس سرور را دوباره روشن می‌کند.
- بازیابی بکاپ با تأیید صریح انجام می‌شود و پیش از جایگزینی فایل‌ها یک بکاپ ایمنی ایجاد می‌شود.

### به‌روزرسانی خود MManager از CLI

دستور اجرا:

    sudo Mmanager

گزینه 8 - Update MManager نصب‌کننده رسمی شاخه main را اجرا می‌کند. داده‌ها، دنیاها، تنظیمات و بکاپ‌ها در مسیرهای جداگانه نگهداری می‌شوند و نصب‌کننده آن‌ها را حذف نمی‌کند.

> توجه: گزینه Update در CLI فقط خود MManager را به‌روزرسانی می‌کند. به‌روزرسانی باینری Minecraft و Rollback آن از تب «نسخه و بروزرسانی» پنل وب انجام می‌شود.

### باز کردن پورت بازی در فایروال

پورت پنل وب با پورت بازی متفاوت است. بعد از نصب سرور، شماره پورت در داشبورد نمایش داده می‌شود. آن را در UFW و Cloud Firewall ارائه‌دهنده VPS باز کنید:

- Java (Vanilla/Paper): پورت نمایش‌داده‌شده با TCP
- Bedrock Dedicated Server: پورت نمایش‌داده‌شده با UDP
- Cross-play: پورت Java با TCP و پورت Geyser با هر دو پروتکل TCP و UDP

نمونه برای پورت‌های پیش‌فرض:

    sudo ufw allow 25565/tcp
    sudo ufw allow 19132/tcp
    sudo ufw allow 19132/udp

اگر MManager به‌دلیل اشغال بودن پورت، پورت دیگری انتخاب کرده است، عدد نمایش‌داده‌شده در داشبورد را جایگزین کنید.


## ۸. کنسول، بازیکنان و RCON
در تب «کنسول RCON» رمز حداقل ۱۶ نویسه‌ای و پورت را تنظیم کنید؛ سپس سرور را Restart کنید. RCON فقط برای Java و Paper/Cross-play پشتیبانی می‌شود. Bedrock Dedicated Server این RCON را ندارد. پنل از 127.0.0.1 به RCON متصل می‌شود، اما سرور Minecraft ممکن است RCON را روی همه interfaceهای شبکه bind کند. چون MManager فایروال را مدیریت نمی‌کند، پیش از فعال‌سازی باید ورودی TCP پورت RCON را در UFW و Cloud Firewall محدود کنید. RCON رمزنگاری ندارد؛ پورت آن را عمومی نگذارید. رمز RCON در server.properties نگهداری می‌شود اما API پنل آن را در پاسخ تنظیمات برنمی‌گرداند. تب «بازیکنان» از RCON برای list، Kick، Ban و Pardon استفاده می‌کند.

## ۹. مانیتورینگ CPU و RAM
تب «مانیتورینگ» اطلاعات فرایند اصلی سرویس Minecraft را از systemd و /proc می‌خواند. CPU بر اساس نمونه‌گیری کوتاه از زمان پردازنده فرایند محاسبه می‌شود و مصرف چند‌هسته‌ای می‌تواند از ۱۰۰٪ بیشتر باشد. RAM بر اساس RSS فرایند است، نه کل مصرف سرویس MManager. وقتی سرور خاموش است مقادیر صفر گزارش می‌شوند.

## ۱۰. مدیریت پلاگین‌ها
مدیریت پلاگین برای Paper و Cross-play فعال است:
1. نام پلاگین را در Modrinth جستجو کنید.
2. نسخه سازگار با نسخه Minecraft فعلی و loaderهای Paper/Spigot انتخاب می‌شود.
3. نصب و حذف فقط وقتی سرور خاموش است انجام می‌شود.
4. فایل دانلودی با SHA-512 در صورت ارائه hash توسط Modrinth بررسی می‌شود.
پلاگین‌ها کد اجرایی شخص ثالث هستند؛ فقط پروژه‌های معتبر را نصب کنید. این قابلیت برای Vanilla و Bedrock در دسترس نیست.

## تنظیمات پیشرفته Geyser در Cross-play

در تب «Geyser» می‌توان پورت Bedrock را (که در نسخه فعلی Geyser روی TCP و UDP گوش می‌دهد)، آدرس و پورت مقصد Java، نوع احراز هویت Floodgate/Online، انتقال MOTD، انتقال تعداد بازیکنان و حالت Debug را تغییر داد. مقادیر قبل از ذخیره اعتبارسنجی می‌شوند و ساختار YAML موجود حفظ می‌شود؛ پس از ذخیره، برای اعمال تنظیمات باید سرور را Restart کنید. این بخش فقط برای سرور Cross-play در دسترس است.

## ۱۱. به‌روزرسانی و Rollback نسخه Minecraft
در تب «نسخه و بروزرسانی» نسخه مقصد را انتخاب کنید. پیش از ارتقا بکاپ کامل ساخته می‌شود و سرور در صورت روشن بودن متوقف می‌شود. برای Java فایل JAR و برای Bedrock فایل‌های اجرایی/runtime نسخه جدید جایگزین می‌شوند؛ دنیا و تنظیمات اصلی Bedrock حفظ می‌شوند. پس از ارتقا نسخه در رجیستری MManager ثبت می‌شود. در صورت شکست، بازگردانی خودکار تلاش می‌شود. دکمه Rollback آخرین بکاپ ارتقای موفق را بازیابی می‌کند و پیش از آن از وضعیت فعلی بکاپ ایمنی می‌سازد. سازگاری پلاگین‌ها و فضای آزاد دیسک را قبل از ارتقا بررسی کنید.

## ۱۲. موارد خارج از دامنه
بازکردن خودکار پورت‌های بازی در UFW یا Cloud Firewall عمداً پیاده‌سازی نشده است. انتخاب خانواده آدرس IPv4/IPv6 در پنل از طریق فیلتر شبکه systemd برای هر سرویس اعمال می‌شود؛ در RakNet قدیمی پورت IPv6 جداست و در NetherNet جدید پورت signaling مشترک است. پورت Java از TCP، پورت Bedrock قدیمی از UDP، پورت‌های gameplay در NetherNet از UDP و پورت Geyser در Cross-play از هر دو TCP و UDP استفاده می‌کند. RCON/مدیریت بازیکن برای Bedrock و مدیریت پلاگین برای Vanilla/Bedrock پشتیبانی نمی‌شود.


## ۱۳. رفع اشکال مانیتورینگ و لاگ
در نسخه 0.5.0 خواندن CPU از فیلدهای صحیح `/proc/PID/stat` انجام می‌شود و نام فرایندهایی که فاصله یا پرانتز دارند باعث جابه‌جایی فیلدها نمی‌شود. مانیتورینگ هنگام بازبودن تب هر ۵ ثانیه تازه می‌شود و خطای API داخل همان بخش نمایش داده می‌شود. فرمان `journalctl` نیز با ترتیب آرگومان سازگار با sudoers اجرا می‌شود و متن خطای واقعی را برمی‌گرداند.

## ۱۴. واردکردن و بازیابی بکاپ
در تب «بکاپ‌ها» علاوه بر تهیه نسخه پشتیبان، می‌توان فایل بکاپ قبلی با پسوند `.tar.gz` یا `.tgz` را از دستگاه بارگذاری کرد. پس از بارگذاری، در فهرست بکاپ‌ها روی «بازگردانی این بکاپ» بزنید. پیش از جایگزینی فایل‌های سرور، MManager یک بکاپ ایمنی از وضعیت فعلی می‌سازد. فایل واردشده باید در قالب بکاپ خود MManager باشد و شامل `server.properties` و باینری سرور باشد.

## ۱۵. تغییر Edition یا نرم‌افزار سرور
تب «تغییر نوع سرور» امکان تغییر بین Java Vanilla، Java Paper، Bedrock Dedicated Server و Cross-play را فراهم می‌کند. پیش از تغییر، بکاپ کامل گرفته می‌شود.
- تغییر Java به Cross-play یا برعکس، فایل‌های دنیا را حفظ می‌کند. هنگام خروج از Cross-play، فایل‌های اصلی Geyser/Floodgate حذف نمی‌شوند؛ به پوشه غیرفعال منتقل می‌شوند.
- تغییر Java و Bedrock تبدیل فرمت دنیا نیست. پوشه کامل سرور قبلی در کنار مسیر سرور با پسوند `.archived-...` نگهداری می‌شود و سرور جدید با دنیای تازه اجرا می‌شود. بکاپ قبلی نیز در فهرست بکاپ‌ها می‌ماند.
- اگر تغییر ناموفق باشد، MManager تلاش می‌کند فایل‌ها و مشخصات قبلی رجیستری را برگرداند.

## ۱۶. مدیریت مپ و Resource Pack
تب «مدیریت مپ» برای Java فایل ZIP و برای Bedrock فایل MCWORLD یا ZIP شامل یک دنیای دارای `level.dat` را بارگذاری می‌کند. نام پوشه باید یکتا باشد. برای فعال‌کردن یک مپ، از فهرست دنیاها آن را انتخاب کنید؛ پیش از تغییر، بکاپ گرفته می‌شود. بارگذاری و انتخاب مپ فقط در حالت خاموش بودن سرور انجام می‌شود یا در زمان فعال‌سازی، سرور موقتاً متوقف و دوباره راه‌اندازی می‌شود.

تب «Resource Pack»:
- Java و Cross-play: آدرس HTTPS بسته و SHA-1 اختیاری را در `server.properties` تنظیم می‌کند. در Cross-play این URL برای کلاینت‌های Java است و Geyser لزوماً آن را برای Bedrock تبدیل نمی‌کند.
- Bedrock: فایل `.mcpack` را بارگذاری و به دنیای فعال متصل می‌کند. نصب/حذف فقط وقتی سرور خاموش است انجام می‌شود.
- برای اعمال تغییرات، سرور را Restart کنید.

## ۱۷. تفاوت مود و پلاگین
پلاگین برای Paper است و از تب «پلاگین‌ها» مدیریت می‌شود. مود به Loaderهایی مانند Fabric یا Forge نیاز دارد و معادل پلاگین نیست. نسخه 0.7.0 هنوز نصب Loaderهای Fabric/Forge و مدیریت چرخه عمر مودها را ارائه نمی‌کند؛ تب مودها در این نسخه توضیحی است و از نصب فایل‌های ناسازگار جلوگیری می‌کند.


## ۱۸. تنظیمات انتخابی و منویی
در تب «تنظیمات سرور»، گزینه‌هایی که مقادیر محدود و مشخص دارند به‌صورت فهرست انتخابی نمایش داده می‌شوند:
- Game Mode: در Java شامل Survival، Creative، Adventure و Spectator؛ در Bedrock شامل Survival، Creative و Adventure.
- Difficulty: Peaceful، Easy، Normal و Hard.
- گزینه‌های روشن/خاموش مانند PvP، Whitelist، Allow Cheats و Command Blocks به‌صورت انتخاب فعال/غیرفعال.
- سطح دسترسی پیش‌فرض بازیکنان Bedrock: Visitor، Member یا Operator.
- نوع دنیا و گزینه‌های عددی نیز متناسب با Edition کنترل مناسب دارند.

## ۱۹. کنسول مستقیم بازی
تب «کنسول بازی» برای Java و Cross-play از RCON استفاده می‌کند. RCON را فعال و رمز حداقل ۱۶ کاراکتری تنظیم کنید، سپس سرور را Restart کنید. ورودی کنسول هم دستورهایی مانند `op` و `give` را می‌پذیرد و هم دکمه «ارسال پیام به چت» دارد که پیام را با دستور `say` به بازیکنان می‌فرستد. RCON رمزنگاری ندارد؛ پورت آن را در اینترنت باز نکنید و فقط دسترسی localhost را نگه دارید.

در Bedrock Dedicated Server، RCON استاندارد وجود ندارد. MManager یک کانال FIFO محلی برای stdin سرور آماده می‌کند. در اولین استفاده پس از به‌روزرسانی، اگر سرور روشن باشد یک بار Restart می‌شود تا این کانال فعال شود؛ خروجی دستورها را در تب لاگ ببینید.

## ۲۰. مدیریت بازیکنان و سطح دسترسی
تب «بازیکنان» سه فهرست جدا دارد: آنلاین، آفلاین/شناخته‌شده و ادمین‌ها. از هر فهرست، عملیات متناسب با Edition در دسترس است:
- Java و Cross-play: Kick، Ban، Unban، OP و Deop. سطح OP از ۱ تا ۴ قابل انتخاب است؛ برای بارگذاری سطح جدید، سرور Restart می‌شود.
- Bedrock: Kick، OP/Deop و انتخاب نقش Operator، Member یا Visitor. این نقش‌ها در `permissions.json` با XUID بازیکن ذخیره و با فرمان `permission reload` اعمال می‌شوند.
- فهرست بازیکنان Java از RCON و فایل‌های `usercache.json`، `ops.json` و فایل‌های ban خوانده می‌شود. برای نمایش آنلاین‌های Java باید RCON فعال باشد.
- در Bedrock، بازیکنان شناخته‌شده از Allowlist و رخدادهای اتصال در لاگ‌ها جمع‌آوری می‌شوند.

**محدودیت واقعی Bedrock:** BDS فهرست Ban/Pardon بومی مشابه Java ندارد. اگر `allow-list=true` باشد می‌توان بازیکن را از Allowlist حذف یا دوباره اضافه کرد؛ این کار Ban واقعی نیست و بدون فعال‌بودن Allowlist مانع ورود بازیکن نمی‌شود. MManager این تفاوت را در UI پنهان نمی‌کند.

## ۲۱. رفع خطای sudo و no_new_privileges
در نسخه 0.7.0، لاگ هر سرور در فایل جداگانه `/var/log/mmanager/servers/NAME.log` ذخیره می‌شود و با logrotate چرخش روزانه دارد. Core و Web برای خواندن لاگ‌ها نیازی به عضویت در گروه `systemd-journal` یا اجرای `sudo` ندارند. کنترل start/stop/restart سرویس بازی از طریق PolicyKit و Rule محدود به واحدهای `mmanager-mc@NAME.service` انجام می‌شود. `NoNewPrivileges=true` فعال باقی می‌ماند.

نصب‌کننده، فایل‌های systemd، مجوزها و PolicyKit را تنظیم می‌کند؛ هیچ تغییری در UFW یا Firewall ارائه‌دهنده VPS انجام نمی‌دهد.


## ۲۲. حذف کامل MManager

برای حذف خود برنامه، CLI را با دسترسی root اجرا کنید:

```bash
sudo Mmanager
```

گزینه ۹ یعنی `Delete MManager` را انتخاب کنید و برای تأیید عبارت `DELETE` را دقیقاً وارد کنید. این عملیات سرویس‌های MManager و سرویس‌های Minecraft مدیریت‌شده را متوقف می‌کند، فایل‌های اجرایی، تنظیمات احراز هویت و یکپارچه‌سازی‌های systemd/PolicyKit را حذف می‌کند. **دنیاها، فایل‌های سرور و بکاپ‌ها در `/var/lib/mmanager` حفظ می‌شوند** و لاگ‌ها نیز برای بررسی باقی می‌مانند. اگر قصد حذف داده‌ها را هم دارید، پس از بررسی دستی مسیرهای `/var/lib/mmanager` و `/var/log/mmanager` را حذف کنید. فایروال سیستم یا ارائه‌دهنده VPS تغییر داده نمی‌شود.
