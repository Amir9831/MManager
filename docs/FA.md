# راهنمای فارسی MManager

**MManager** ابزاری برای نصب و مدیریت سرورهای Minecraft روی Ubuntu است. این راهنما بخش پنل وب عمومی، نصب اولیه و مدیریت تنظیمات پنل از طریق CLI را توضیح می‌دهد.

## ۱. نصب

سیستم‌عامل‌های پشتیبانی‌شده در نسخه فعلی: Ubuntu 22.04، 24.04 و 26.04 به‌همراه systemd.

نصب را با دسترسی مدیریتی اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/Amir9831/MManager/main/install.sh | sudo bash
```

اسکریپت وابستگی‌ها و سرویس‌ها را نصب می‌کند، رمز مدیر را می‌سازد و یک مسیر تصادفی با طول و آنتروپی بالا برای پنل تولید می‌کند.

در پایان نصب، آدرس پنل با این قالب نمایش داده می‌شود:

```text
http://PUBLIC_IP:PANEL_PORT/RANDOM_PATH/
```

- `PUBLIC_IP`: آدرس IPv4 عمومی سرور
- `PANEL_PORT`: پورت TCP پنل
- `RANDOM_PATH`: مسیر محرمانه و تصادفی پنل

رمز مدیر و آدرس پنل در فایل زیر ذخیره می‌شوند:

```text
/root/mmanager-admin-credentials.txt
```

سطح دسترسی این فایل باید فقط برای root باشد (0600). آن را در اختیار دیگران قرار ندهید.

## ۲. دسترسی از اینترنت و فایروال

پنل وب و API موردنیاز مرورگر روی یک پورت TCP مشترک ارائه می‌شوند. سرویس Core/API داخلی جداگانه روی loopback باقی می‌ماند و نباید مستقیماً روی اینترنت منتشر شود.

اگر UFW روی سرور فعال باشد، نصب‌کننده تلاش می‌کند پورت پنل را باز کند. در هر صورت، در پنل مدیریت VPS یا Cloud Firewall نیز باید پورت TCP انتخاب‌شده را مجاز کنید.

برای مشاهده وضعیت UFW:

```bash
sudo ufw status
```

اگر لازم بود پورت را دستی باز کنید (عدد را با پورت پنل خود جایگزین کنید):

```bash
sudo ufw allow PANEL_PORT/tcp
```

در صورت وجود فایروال در سطح ارائه‌دهنده VPS، قانون ورودی TCP متناظر را آنجا نیز اضافه کنید.

## ۳. مدیریت پنل از CLI

CLI را با دسترسی مدیریتی اجرا کنید:

```bash
sudo Mmanager
```

از منوی اصلی وارد گزینه **Web panel management** شوید.

### تغییر یا تولید مجدد Path

گزینه تغییر Path را انتخاب کنید. می‌توانید یک مسیر جدید با حداقل ۲۴ نویسه URL-safe وارد کنید یا ورودی را خالی بگذارید تا مسیر تصادفی جدید ساخته شود.

پس از ذخیره، سرویس وب راه‌اندازی مجدد می‌شود. آدرس قبلی دیگر معتبر نخواهد بود؛ آدرس جدید را از گزینه نمایش آدرس پنل دریافت کنید.

### تغییر رمز مدیر

رمز جدید باید حداقل ۱۲ نویسه داشته باشد و دوبار برای تأیید وارد شود. رمز به‌صورت Argon2id هش می‌شود و توکن نشست‌های قبلی باطل می‌شوند؛ بنابراین کاربران باید دوباره وارد پنل شوند.

### تغییر پورت

پورت باید عددی بین 1024 تا 65535 باشد و توسط برنامه دیگری اشغال نشده باشد. پس از تغییر، سرویس وب مجدداً راه‌اندازی می‌شود. اگر پورت جدید در UFW یا Cloud Firewall مجاز نباشد، از بیرون سرور به پنل دسترسی نخواهید داشت.

### نمایش آدرس فعلی

گزینه نمایش URL، آدرس پنل را با IP عمومی، پورت و Path فعلی چاپ می‌کند.

## ۴. امنیت

- Path تصادفی یک لایه دفاعی اضافه است؛ جایگزین رمز عبور و احراز هویت نیست.
- احراز هویت Argon2id و Bearer Token را غیرفعال نکنید.
- Listener داخلی این نسخه از HTTP استفاده می‌کند. برای انتشار واقعی روی اینترنت، HTTPS را با یک Reverse Proxy معتبر مانند Nginx یا Caddy فعال کنید.
- پورت Core/API داخلی را در فایروال عمومی باز نکنید.
- فایل اطلاعات مدیر را با مجوز 0600 نگه دارید و URL کامل پنل را محرمانه تلقی کنید.
- تغییر Path باعث بی‌اعتبارشدن آدرس قبلی می‌شود؛ URL جدید را در محل امن نگه دارید.

## ۵. نصب مجدد و حفظ تنظیمات

نصب مجدد، فایل‌های تنظیمات موجود در `/etc/mmanager` و داده‌ها، دنیاها و بکاپ‌های موجود در `/var/lib/mmanager` را حفظ می‌کند. اگر قبلاً رمز یا Path پنل ساخته شده باشد، نصب مجدد آن‌ها را به‌صورت خودکار تغییر نمی‌دهد.

## ۶. عیب‌یابی سریع

وضعیت سرویس وب:

```bash
sudo systemctl status mmanager-web --no-pager
```

مشاهده لاگ سرویس وب:

```bash
sudo journalctl -u mmanager-web -n 100 --no-pager
```

راه‌اندازی مجدد سرویس:

```bash
sudo systemctl restart mmanager-web
```

اگر پنل از داخل سرور در دسترس است اما از اینترنت باز نمی‌شود، ابتدا پورت TCP را در UFW و سپس در Cloud Firewall ارائه‌دهنده VPS بررسی کنید. همچنین مطمئن شوید IP عمومی و پورت درج‌شده در URL درست هستند.

---

این قابلیت‌ها در حال حاضر یک نسخه اولیه کاربردی هستند. پیش از استفاده حساس یا عملیاتی، نسخه پشتیبان تهیه کنید و دسترسی HTTPS و فایروال را بررسی کنید.

## ۷. مدیریت تک‌سرور در نسخه جدید

پنل وب فقط یک نمونه Minecraft را مدیریت می‌کند. پس از نصب اولین سرور، فرم راه‌اندازی اولیه دیگر نمایش داده نمی‌شود و پنل به داشبورد همان سرور می‌رود. سرورهای موجود و مسیر دنیاهای قبلی در نصب مجدد حذف نمی‌شوند.

### انتخاب Edition و نسخه

در اولین ورود، یکی از حالت‌های زیر را انتخاب کنید:

- **Java Edition:** سرور رسمی Vanilla یا Paper؛ فهرست نسخه‌های Release از Manifest رسمی Mojang دریافت می‌شود.
- **Bedrock Edition:** نرم‌افزار رسمی Bedrock Dedicated Server برای Linux؛ فهرست نسخه‌های پایدار و checksumها از مخزن داده نسخه‌ها دریافت می‌شوند و فایل اجرایی از دامنه رسمی Minecraft دانلود می‌شود.
- **Cross-play:** سرور Paper به‌همراه Geyser و Floodgate؛ فهرست نسخه‌ها به نسخه‌های دارای build پایدار Paper محدود می‌شود.

برای نصب اولیه، پذیرش EULA لازم است. در حالت Bedrock نیز باید شرایط مجوز نرم‌افزار را بپذیرید.

### تنظیمات سرور

بخش «تنظیمات سرور» فایل server.properties را می‌خواند و تنظیمات پیش‌فرض Java یا Bedrock را از قالب‌های داخل پروژه بارگذاری می‌کند. تغییرات پس از ذخیره روی دیسک ثبت می‌شوند؛ برای اعمال تنظیماتی که نیازمند راه‌اندازی مجدد هستند، سرور را Restart کنید.

قالب‌های مرجع در مسیر mmanager/templates/ قرار دارند:
- java-server.properties
- bedrock-server.properties
- crossplay-geyser.yml

### لاگ و بکاپ

- بخش «لاگ سرور» خروجی سرویس systemd را نشان می‌دهد و هنگام باز بودن این بخش هر ۵ ثانیه تازه می‌شود.
- تهیه بکاپ، در صورت روشن بودن سرور آن را موقتاً متوقف می‌کند تا آرشیو سازگار تهیه شود و سپس سرور را دوباره روشن می‌کند.
- بازیابی بکاپ با تأیید صریح انجام می‌شود و پیش از جایگزینی فایل‌ها یک بکاپ ایمنی ایجاد می‌شود.

### به‌روزرسانی خود MManager از CLI

دستور اجرا:

    sudo Mmanager

گزینه 8 - Update MManager نصب‌کننده رسمی شاخه main را اجرا می‌کند. داده‌ها، دنیاها، تنظیمات و بکاپ‌ها در مسیرهای جداگانه نگهداری می‌شوند و نصب‌کننده آن‌ها را حذف نمی‌کند.

> توجه: گزینه Update در CLI فقط خود MManager را به‌روزرسانی می‌کند. به‌روزرسانی باینری Minecraft و Rollback آن از تب «نسخه و بروزرسانی» پنل وب انجام می‌شود.

### باز کردن پورت بازی در فایروال

پورت پنل وب با پورت بازی متفاوت است. بعد از نصب سرور، شماره پورت در داشبورد نمایش داده می‌شود. آن را در UFW و Cloud Firewall ارائه‌دهنده VPS باز کنید:

- Java: پورت نمایش‌داده‌شده با TCP
- Bedrock: پورت نمایش‌داده‌شده با UDP
- Cross-play: هر دو پورت TCP جاوا و UDP بدراک

نمونه برای پورت‌های پیش‌فرض:

    sudo ufw allow 25565/tcp
    sudo ufw allow 19132/udp

اگر MManager به‌دلیل اشغال بودن پورت، پورت دیگری انتخاب کرده است، عدد نمایش‌داده‌شده در داشبورد را جایگزین کنید.


## ۸. کنسول، بازیکنان و RCON
در تب «کنسول RCON» رمز حداقل ۱۶ نویسه‌ای و پورت را تنظیم کنید؛ سپس سرور را Restart کنید. RCON فقط برای Java و Paper/Cross-play پشتیبانی می‌شود. Bedrock Dedicated Server این RCON را ندارد. پنل از 127.0.0.1 به RCON متصل می‌شود، اما سرور Minecraft ممکن است RCON را روی همه interfaceهای شبکه bind کند. چون MManager فایروال را مدیریت نمی‌کند، پیش از فعال‌سازی باید ورودی TCP پورت RCON را در UFW و Cloud Firewall محدود کنید. RCON رمزنگاری ندارد؛ پورت آن را عمومی نگذارید. رمز RCON در server.properties نگهداری می‌شود اما API پنل آن را در پاسخ تنظیمات برنمی‌گرداند. تب «بازیکنان» از RCON برای list، Kick، Ban و Pardon استفاده می‌کند.

## ۹. مانیتورینگ CPU و RAM
تب «مانیتورینگ» اطلاعات فرایند اصلی سرویس Minecraft را از systemd و /proc می‌خواند. CPU بر اساس نمونه‌گیری کوتاه از زمان پردازنده فرایند محاسبه می‌شود و مصرف چند‌هسته‌ای می‌تواند از ۱۰۰٪ بیشتر باشد. RAM بر اساس RSS فرایند است، نه کل مصرف سرویس MManager. وقتی سرور خاموش است مقادیر صفر گزارش می‌شوند.

## ۱۰. مدیریت پلاگین‌ها
مدیریت پلاگین برای Paper و Cross-play فعال است:
1. نام پلاگین را در Modrinth جستجو کنید.
2. نسخه سازگار با نسخه Minecraft فعلی و loaderهای Paper/Spigot انتخاب می‌شود.
3. نصب و حذف فقط وقتی سرور خاموش است انجام می‌شود.
4. فایل دانلودی با SHA-512 در صورت ارائه hash توسط Modrinth بررسی می‌شود.
پلاگین‌ها کد اجرایی شخص ثالث هستند؛ فقط پروژه‌های معتبر را نصب کنید. این قابلیت برای Vanilla و Bedrock در دسترس نیست.

## ۱۱. به‌روزرسانی و Rollback نسخه Minecraft
در تب «نسخه و بروزرسانی» نسخه مقصد را انتخاب کنید. پیش از ارتقا بکاپ کامل ساخته می‌شود و سرور در صورت روشن بودن متوقف می‌شود. برای Java فایل JAR و برای Bedrock فایل‌های اجرایی/runtime نسخه جدید جایگزین می‌شوند؛ دنیا و تنظیمات اصلی Bedrock حفظ می‌شوند. پس از ارتقا نسخه در رجیستری MManager ثبت می‌شود. در صورت شکست، بازگردانی خودکار تلاش می‌شود. دکمه Rollback آخرین بکاپ ارتقای موفق را بازیابی می‌کند و پیش از آن از وضعیت فعلی بکاپ ایمنی می‌سازد. سازگاری پلاگین‌ها و فضای آزاد دیسک را قبل از ارتقا بررسی کنید.

## ۱۲. موارد خارج از دامنه
بازکردن خودکار پورت‌های بازی در UFW یا Cloud Firewall عمداً پیاده‌سازی نشده است. پورت Java از TCP و Bedrock از UDP استفاده می‌کند؛ Cross-play به هر دو نیاز دارد. RCON/مدیریت بازیکن برای Bedrock و مدیریت پلاگین برای Vanilla/Bedrock پشتیبانی نمی‌شود.
